## まとめ

**JWT って何？**

サーバーが発行する「改ざんできない通行証」の文字列です。ログインのときにもらい、ログイン中の操作では毎回それを見せます。

**JWT は何の 3 つでできている？**

`header.payload.signature` の 3 つを `.` でつないだものです。payload に `id` や `exp`（期限）などのデータが入り、signature は秘密鍵で作ったはんこです。

**payload は誰でも読める？**

読めます。暗号化はされていないので、パスワードなどの秘密は入れません。

**なぜ書き換えられない？**

はんこ（signature）は、サーバーだけが持つ秘密鍵がないと作れないからです。payload を書き換えると、はんこと合わなくなって弾かれます。そのため、秘密鍵は `.env` に置いて Git に上げません。

**JWT 認証の流れは？**

```
ログイン   → サーバーが JWT を作って（jwt.sign）、Cookie に入れて返す
ログイン中 → ブラウザが Cookie を自動で送る → サーバーが確かめる（jwt.verify） → だめなら 401
ログアウト → サーバーが Cookie を消す
```

確かめる処理は「ミドルウェア」にまとめて、各 API の前に挟みます。

**JWT は DB に保存する？**

しません。サーバーは秘密鍵で確かめるだけです。DB に保存するのはユーザーで、パスワードは**ハッシュにして**保存します（bcrypt）。

**ログアウトしたら、JWT は使えなくなる？**

ブラウザから消えるだけで、コピーされていたら期限まで使えます。そのため、期限は短くします（15 分〜1 時間）。

**トークンはどこに保存する？**

| 保存場所 | 送り方 | 弱いところ |
| --- | --- | --- |
| **HttpOnly Cookie（おすすめ）** | ブラウザが自動で送る | 特になし（`sameSite` を設定する） |
| localStorage | 自分で `Authorization: Bearer ...` を付ける | XSS で盗まれる |

**フロントは何をすればいい？**

```ts
// Cookie 方式：credentials を付けるだけ
fetch("/api/v1/users/me", { credentials: "include" });

// ヘッダー方式：毎回トークンを付ける
fetch("/api/v1/users/me", { headers: { Authorization: `Bearer ${token}` } });
```

**401 が返ってきたら、ログイン画面に戻します。**

**セッション方式と何が違う？**

セッションは、サーバーが「この ID は誰か」を覚えておく方式です。JWT は、サーバーが何も覚えず、トークンの中身で判断します。Auth0、Firebase などの認証サービスは JWT を使います。

**AI に頼むときは、どう言えばいい？**

使う言葉が分かっていれば十分です。たとえば次のように頼みます。

> Express で JWT 認証を作って。ログインで JWT を発行して HttpOnly Cookie に保存し、認証ミドルウェアで検証して、失敗したら 401 を返して。

**AI が書いたコードで、何を確認する？**

| 確認すること | なぜ |
| --- | --- |
| 秘密鍵が `process.env` から読まれている | コードに直接書くと、Git で漏れる |
| Cookie に `httpOnly: true` がある | ないと XSS で盗まれる |
| `expiresIn` で期限が付いている | ないと永久に使える |
| パスワードを bcrypt などでハッシュにしている | 平文で保存しない |
| レスポンスにパスワード（ハッシュ）を含めていない | フロントに返す必要がない |
| 確かめるのに `jwt.verify` を使っている（`jwt.decode` ではない） | `decode` は はんこを確かめない |
