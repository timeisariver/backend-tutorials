## まとめ

**PostgreSQL って何？**

RDBMS（リレーショナル・データベース・マネジメント・システム）の一つ。データを**表（テーブル）**に入れて、表どうしを**関連（リレーション）**でつなぐ、という仕組み。MySQL などの仲間。

**SQL って何？**

DB に「これを保存して」「これを見せて」とお願いするための言葉です（Structured Query Language の略）。PostgreSQL も MySQL も、同じ SQL で操作できます。GUI ツールや ORM（Prisma など）も、裏では SQL を送っています。

**DB はどこにある？**

Web サーバの後ろにあって、データをしまっておく場所です。フロントは直接さわらず、API を通して使います。

**なぜ Docker を使ったの？**

PC に直接インストールせずに、PostgreSQL の環境をすぐ作れて、すぐ消せるからです。PC を汚さず、みんな同じ環境で動かせます。

**なぜアプリ用のユーザを分けるの？**

管理者（postgres）は何でもできてしまうからです。アプリには必要な権限だけを持たせて、乗っ取られたときの被害を小さくします。API キーの権限（スコープ）と同じ考え方です。

**テーブルって何？**

TypeScript の型定義のようなものです。列には型・NOT NULL・DEFAULT があって、id（主キー）で1行を特定します。

**主キーと外部キーのちがいは？**

- 主キー：そのテーブルの中で1行を特定する id。重複しない、空にならない。
- 外部キー：ほかのテーブルの id を指す列（例：`posts.user_id → users.id`）。存在しない id は入れられない。

**CRUD は？**

|  | SQL | API |
| --- | --- | --- |
| Create（作る） | `INSERT` | `POST` |
| Read（読む） | `SELECT` | `GET` |
| Update（変える） | `UPDATE` | `PATCH` |
| Delete（消す） | `DELETE` | `DELETE` |

API の裏で、この SQL が動いています。

**WHERE を忘れると？**

UPDATE や DELETE が**全件**に効いてしまいます。実行する前に、同じ WHERE で SELECT して対象を確かめます。

**DELETE・TRUNCATE・DROP のちがいは？**

- `DELETE`：行を消す（WHERE で選べる）
- `TRUNCATE`：行を全部まとめて消す（テストデータを空にするときなど）
- `DROP TABLE`：テーブルごと消す

**なぜテーブルを分けるの？（正規化）**

同じデータを何か所にも持たないためです。外部キーでつないで、JOIN で組み立て直します。多対多は中間テーブルで表します。

**一覧の並び順は？**

`ORDER BY` をつけないと、順番は保証されません。ページネーションは `ORDER BY` + `LIMIT` / `OFFSET` で作ります。

**バックアップは何のため？**

事故で消したデータを戻したり、本番のデータを手元にコピーしたりするためです。`pg_dump` で SQL ファイルに書き出して、`psql` で流しこめば戻せます（phpMyAdmin のエクスポート / インポートと同じ）。

**エラーが出たら？**

「SQL の書き方のまちがい」か「権限がない」かを見分けます。
